# 多 VPS 节点

## 场景与边界

用户在「节点」提交名称和公网 IPv4，在自己的 VPS 执行原生安装命令。节点生成本机身份并等待管理员审批；管理员把节点分配给工作空间后，用户才能在服务中选择它。普通用户不具备更新、重启、停用或分配权限。

节点列表使用卡片：宽屏三列、中屏两列、移动端单列。卡片按名称/状态、公网地址、系统架构、服务和连接数、版本、管理操作排列；详情承载分配、诊断和操作记录。离线统计必须标记为旧数据。

独立 VPS 节点复用 Server 程序，但发布版本独立判断。`release-manifest.json` 的 `node_version` 记录最近一次实际发布的节点版本；只有节点运行逻辑、其使用的共享代码、Caddy 或安装/更新助手变化时，才声明 `node` 组件并将 `node_version` 更新为本次版本。仅 Web 或管理端变化时保留原值，不构建节点安装包。节点安装默认版本与可更新目录均以此值为准；内置节点随管理 Server 进程显示版本。

场景：管理 Server 更新至 `0.2.19`，节点代码仍为 `0.2.18`。已运行 `0.2.18` 的 VPS 不显示更新；较旧 VPS 的目标和新节点安装命令仍为 `0.2.18`。以后节点代码发布新版时，再提供相应架构的安装与更新；安装包校验、身份保留和回退流程继续执行。

同一服务可以选择多个 VPS，A 记录指向健康入口，HTTPS 的 AAAA 可以同时指向 NAS。协调器不能让直连的单 A 写入覆盖多节点记录。DNS 缓存和客户端重试决定实际恢复时间，不承诺秒切或长连接无损迁移。管理 Server 保持单实例，管理失联最多 45 秒后停止转发。

曾由 Nexo 管理 DNS 的域名穿透服务切回内置节点后，管理意图保存在已有 DNS 状态记录中。内置入口尚未就绪时撤回旧入口的 A；即使所有 A 已清空或 Server 重启，也继续检查并在内置入口恢复健康后写回业务子域名的独立 A。根域名、泛域名和 AAAA 不随节点选择改动，外部修改的记录仍拒绝覆盖。停用、删除、改为反向代理或不再绑定域名时，不因历史状态重新接管解析。

更新仅维护 Nexo 节点及随包 Caddy，不更新宿主机操作系统。管理员单节点/批量更新共用顺序任务：检查、下载校验、安装重启、健康核验。更新提示明确说明关联服务会中断，用户点击「开始更新」即执行，不要求额外勾选、健康备用入口、DNS TTL 等待或连接排空。安装期间各服务继续由 DNS 协调器按健康和授权处理；无健康备用的服务仍可保留符合当前配置、授权且上次同步无错误的已有受管 A。启动失败回退，结果未知暂停队列。

场景：日本节点仍有 Emby 播放或 WebSocket 长连接，且关联服务没有备用 IPv4 入口。管理员看到中断提示后开始更新，安装包下载校验完成即安装重启，不因连接数非零暂停，也不要求再次确认中断。安装核验和实际版本核对仍执行；已有更新任务处于撤出或排空阶段时，继续执行也按此规则安装。独立的「重启节点服务」操作沿用原有切流、TTL、排空和中断确认流程。

场景：单入口服务更新时公网 IP 不变，保留 DNS 但仍有进程重启中断；双入口服务的 DNS 由协调器排除维护节点，更新本身不等待切流完成。同一节点混合承载两类服务时分别处理。维护期间的探测和健康核验继续执行，保留解析不代表节点健康；停用、删除、撤权、域名或地址变化仍执行原有清理与外部 DNS 修改保护。

### 节点更新与业务恢复分开确认（2026-10-06）

场景：VPS 从 0.2.18 升至 0.2.20，更新助手已确认目标版本、新进程、管理连接和本机健康，关联的 6 个服务中仅 Synctv 回源拒绝连接。节点安装已经成功，后端故障不应让其余 5 个服务一直停留在维护状态。

节点核验使用当前任务的助手安装成功报告、实际目标版本及有效的节点在线和审批状态。确认后退出节点维护，各服务继续按现有配置、Agent 回源、公网探测和授权判断恢复资格，故障服务不会因节点更新成功被判为健康。恢复阶段只等待健康域名穿透服务的 DNS 同步；无域名、直接回源或不健康的服务不阻塞队列，未恢复健康的服务名称记入节点维护记录。未知安装结果、版本不符、启动回退或节点失联仍暂停；健康服务的 DNS 同步失败仍暂停并支持重试。已经暂停的安装任务只核对结果，仍需管理员重试恢复入口。

验证目标：混合健康与故障服务时维护能够完成、故障入口仍无 DNS 资格；全部后端故障或无关联服务时安装成功仍可完成；健康服务 DNS 失败仍可重试；旧任务报告、错误版本及未确认状态不能结束维护；单入口 DNS 保留和既有权限保护继续通过回归。

### 添加节点收尾场景与线框（编码前）

凭证整合（用户确认）：安装页仅保留「在 VPS 执行 → 复制安装命令 → 有效期」。复制内容以带引号的 here-document 将一次性凭证传入安装器标准输入，用户无需第二次粘贴；不传入程序参数、环境变量或 systemd 配置。安装器在包管理等子进程运行前读取凭证，保留终端手动输入兼容路径。命令现在包含接入身份，明确提示勿分享；有效期和使用后失效规则不变。

文案与字段：首次填写仅保留名称、公网 IPv4 和系统要求；安装页突出「复制命令，在 VPS 执行」。版本、架构及端口解释折叠到「安装选项 · HTTPS 端口」，单一版本显示只读文字。默认不重复展示等待安装、自动刷新、失败可重试等说明；缺包、过期、注册成功各显示一条反馈。凭证轮换入口放入安装选项，旧命令随凭证轮换失效。

- 新申请：名称/IP → 复制含凭证的安装命令（可展开安装选项）→ 自动显示注册结果。命令使用配置的公网 HTTPS 管理地址，不使用浏览器当前的局域网地址。
- 暂未安装、凭证遗失或过期：本人工作空间的申请者或管理员从详情继续安装，重新生成 30 分钟凭证，旧凭证立即失效；已注册节点不允许重置身份。

1. 节点身份、审批分配及增量迁移；验证凭证重放、工作空间隔离和旧服务兼容。
2. 多节点连接、健康和 DNS；验证各节点故障独立、A/AAAA 互不覆盖、失联撤销、统一额度。
3. 原生安装及持久化更新任务；验证双架构、版本约束、重启恢复、失败回退和排空。
4. 节点卡片和服务表单；验证窄屏、键盘、权限与更新进度。

## 延迟与选择场景

延迟是 Agent → VPS 的实测往返时间，不代表访问者 → VPS 的网络质量。自动模式使用平滑延迟、最小改善幅度和驻留时间抑制频繁切换；手动模式在首选节点故障时切换到所选备用，首选恢复健康后回切。DNS 缓存和现有连接不随选择立即迁移。

### DNS 与入口健康优化（2026-10-01）

场景：端口可以建立 TCP 连接，但可能由另一项业务占用，或 Caddy 尚未加载本服务的新配置，也可能存在域名或 TLS 证书错误。新节点在实际业务端口上提供只读 `GET /.nexo-relay/probe`；静态响应仅包含 `node_id`、`service_id`、`revision`，使用 `Cache-Control: no-store`。探测路由先于内网重定向和访问认证，其他路径和方法仍执行原有密码保护与转发。管理入口、反向代理和未受多节点 DNS 管理的内置服务不增加此路由。

Server 固定连接候选节点的 IPv4，以业务域名发送 Host 和 TLS SNI，HTTPS 保持证书校验。禁用代理和重定向，总超时 3 秒，响应限制为 1 KiB；只接受 200 且配置标识完全匹配。公网检查与节点授权、45 秒内的在线状态、当前版本就绪报告及 Agent 回源连通报告一起决定入口资格。它验证入口和链路准备状态，不验证应用登录、403/404、应用功能或访问者网络。

兼容与恢复：节点报告新增 `public_probe_supported`，省略时默认为 false。旧 HTTP/HTTPS 节点继续做 TCP 检查，详情显示「TCP 检查（兼容）」；支持新探测的节点失败后不会降级。协调周期仍为 10 秒，连续三次成功恢复、三次失败撤出，样本有效期为 45 秒，多 A 的 TTL 为 60 秒。检查方式、配置版本或地址改变后重新累计；支持声明改变时立即清除旧公网样本。配置、地址和授权在探测结果落库及 DNS 写入前重新核对，期间发生变更的结果丢弃。DNS 网络等待后再次核对所选入口的综合健康，过期或被清除的探测样本不得发布。

DNS、服务状态及维护备用入口共用综合健康判断。维护节点可以继续接受恢复检查，但退出维护前不进入 DNS 或备用集合；各服务入口的恢复验证仍须匹配当前检查方式、地址和 Agent 回源报告，不作为节点安装成功的共同前提。内置节点缺少公网 IPv4 时只记为该节点检查失败，不阻断其他入口更新或撤出。全部 IPv4 入口不可用时撤出受管 A，详情直接显示「暂无可用 IPv4 入口」。AAAA、泛解析和缓存仍可能影响实际解析，不能将此状态表述为域名必然无法解析。IPv6 直连开关、关闭直连保留 A 及外部 DNS 修改保护保持原有规则。

选择策略改称「回源延迟优先」，节点详情明确「设备到节点」，卡片继续只显示「延迟」。原有平滑、至少改善 10 ms 且 20%、60 秒驻留与三个独立样本的规则保持不变；不加入访问者测速或新评分。

界面提示只显示结论和必要操作；节点错误默认显示简短原因，完整诊断按需展开。入口全部失效直接提示「暂无可用 IPv4 入口／请检查下方节点状态」；状态说明提醒实际访问验证，解析与缓存边界详见本文档。

升级按管理 Server → 分批 VPS 节点进行。原生节点由 Server 组件提供，SQLite 只为既有健康表补列，重复迁移保留节点身份、授权和服务配置。本次仅修改 Server、Web 和节点报告协议；Agent 运行时代码无需变更，未正式发布或部署生产。

### 手机导航与节点组

手机常驻四个入口：首页／服务／设备／更多。更多展开选择列表：节点、域名、账号设置，管理员另有用户管理。选择后关闭，点击外部或 Escape 关闭，键盘可逐项访问；更多内页面激活时保持更多选中。桌面侧栏保持全部资源入口。

节点组由管理员维护和分配；普通用户只读获授权的组。服务选择组后绑定组内节点并使用 DNS 分流、自动低延迟或手动首选策略。编辑组成员时同事务重校验所有关联服务的节点授权、端口和首选节点；失败不部分保存。使用中的组不能直接删除，撤销工作空间前先解除其服务绑定。

### 公网资源与未完成验收

补充端口场景：第二台 VPS 的 80/443 已有业务，用户选择保留它，让 Nexo 验收实例使用 8080/8443。HTTP 入口复用管理 Server 的 `caddy.http_listen` 端口并下发到节点，公网探测使用相同端口；HTTPS 服务使用已有的 `https_port=8443`，HTTP 跳转必须保留该目标端口。所有参与同域名 DNS 切换的入口使用相同公网端口，不能仅在一台机器做不同端口映射。此调整不需要新增界面布局；默认配置继续使用 80/443。

验收配置为管理 Server 的 `[caddy] http_listen = ":8080"`，HTTPS 服务的 `https_port = 8443`。安装器支持 `--http-port 8080 --https-port 8443 --data-port 9891`，用于安装前端口检查和放行提示；实际服务监听仍以控制器下发为准，参数不会擅自更改其他服务。生成的安装命令携带全部三个端口；HTTP 和数据端口来自管理端，HTTPS 检查端口在安装页选择。root 直接执行，普通用户通过 sudo 执行。
