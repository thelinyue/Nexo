# HTTPS 公网端口与 IPv6 直连

## 场景与交互

NAS 入站 443 被限制时，在服务中选择 HTTPS、公网端口 9443。管理入口和其他 443 服务保持原地址。多个服务共用 9443，按域名区分。端口属于服务，换绑 Agent 不改变访问地址。

服务表单沿用现有公网入口分组：

```text
公网入口
  协议 [HTTPS]  主机名 [emby]  域名 [example.com]
  HTTPS 端口 [9443]
  访问地址 https://emby.example.com:9443
访问规则
  [公开访问] [认证访问]
IPv6 直连
  [关闭 / 开启]  与内网重定向互斥
  地址候选 [Agent 的稳定公网 IPv6]
```

IPv6 直连开启后，明确的 A 记录指向 Server，AAAA 指向 Agent；两端使用服务选定的同一端口。纯 IPv4 客户端仍由 Server 转发。客户端自行选择连接路径，不承诺 IPv6 故障时自动回退或播放中迁移。Emby 原生客户端建议使用 Emby 自身认证。

## 实施与验证

1. HTTPS 端口：增量迁移、配置与认证、Caddy 多监听、表单和 URL；验证端口隔离、冲突、会话撤销及旧服务兼容。
2. IPv6 直连：双向能力协商、设备 mTLS 管理连接、Agent Caddy 与取消式回源、Server DNS/证书/授权；验证租户隔离与故障撤销。
3. DNS 提供商：Cloudflare 完整链路后接入阿里云和腾讯云，精确维护 A/AAAA/TXT，不覆盖外部修改。
4. 自动验证与真实验收分开：本机测试不能代替公网 DNS、防火墙、运营商和手机/电视 Emby 验收。先使用独立测试域名。

## 安全边界

DNS 凭据仅在 Server；服务私钥仅在 Agent。授权集中在 Server，不能把原来仅限 loopback 的认证接口直接暴露。管理入口与业务主机名隔离。DNS 撤销不是安全撤销，关闭监听和取消已有连接才是。远端探测默认关闭，仅诊断。

## 配置与启用

### 仅使用自定义 HTTPS 端口

在添加或编辑服务时填写「HTTPS 端口」。默认值 443；9443 等端口会加入访问地址、复制链接和 HTTP 跳转目标。反向代理与 Agent 穿透都支持。此阶段不需要升级 Agent。

在 VPS 防火墙、安全组及容器端口映射中放行对应 TCP 端口。Nexo 会配置 Caddy 监听，但不会修改主机防火墙或 Docker 映射。采用 host 网络的现有部署无需增加容器映射；bridge 网络需自行增加，例如 `9443:9443`。管理入口仍使用原端口。

已有服务增量升级为 443。编辑省略端口、换绑和切换协议不会丢失原值；端口改变会撤销该服务原有 Nexo 访问会话。服务详情保留具体监听失败原因，不以保存成功代替监听生效。

### 启用 IPv6 直连

1. Server 与 Agent 都更新为包含此功能的构建。旧端只使用原 Tunnel。Agent 的 Linux 镜像已内置 Caddy；独立安装可在 `agent.toml` 设置 `caddy_binary`。稳定公网 IPv6 自动发现目前面向 Linux/NAS，非 Linux Agent 不提供地址候选。
2. 在 Server 的 `server.toml` 填写实际公网 IPv4，重启 Server：

   ```toml
   [direct]
   relay_ipv4 = "203.0.113.10" # 替换为 VPS 的实际公网 IPv4
   acme_directory = "https://acme-v02.api.letsencrypt.org/directory"
   probe_enabled = false
   ```

   转发 IPv4 不再从页面输入，使用此配置。Server 可以没有 IPv6。可选探测需要 Server 具备 IPv6 出口，结果只供诊断。
3. 在业务域名的「证书方式」选择 DNS 验证，选择 Cloudflare、阿里云 DNS 或腾讯云 DNSPod，保存具备相应区域读取和记录增删改权限的凭据。凭据只保存在 Server 私有文件中。Server Caddy 必须包含对应 DNS 模块；项目 Dockerfile 已包含三种模块。
4. Agent 使用能看到 NAS 稳定公网 IPv6 的网络。Linux Docker 推荐现有 host 网络；容器内不可见宿主机地址时不会把宿主机地址当作候选。放行 NAS/路由器 IPv6 防火墙的业务 TCP 端口，例如 9443。无需开放 NAS 的 80/443。
5. 使用独立测试子域名新建 HTTPS 穿透服务，填写公网端口，关闭内网重定向，再开启 IPv6 直连。单一地址自动选择；多个候选需选择。地址选择会影响同一 Agent 的所有直连服务。
6. 等待证书签发、Agent 入口就绪和 DNS 写入。服务详情区分转发状态、直连状态、签发错误与 DNS 错误。默认显示「已配置，公网未验证」，需另行进行公网验收。

DNS 为具体业务主机名写入 `A → relay_ipv4` 和 `AAAA → Agent IPv6`，不依赖通配符 A。Cloudflare 必须 DNS only。已有 CNAME、代理、多条同类型访问记录，或不属于 Server 的现有访问记录会阻止接管；需要先核对 DNS，不会自动覆盖。若需接管已有 Server AAAA，Server 地址仍须在后端已有的 `public_ips` 配置中可识别；否则请先手动整理该记录。

内部 `certificate_mode=cloudflare_dns` 保留旧数据库取值以兼容升级，实际服务商由 `dns_provider` 决定；界面统一称为 DNS 验证。

## 停用和故障处理

- 关闭直连保留 A、服务端口与 Tunnel；删除本功能新增的 AAAA，或恢复接管前的 Server AAAA。DNS 清理失败会保留日志重试，外部修改冲突不会被覆盖。清理未完成时不能删除域名或工作空间，以免丢失撤销所需凭据。
- Agent 离线、地址失效、证书过期或配置撤销会停止直连。认证通道不可用时新请求拒绝访问；已有连接由控制通道的最长 45 秒失效机制以及配置变更通知撤销。DNS 撤销还受协调周期和缓存 TTL 影响。
- 有效旧证书在续期失败时继续使用。私钥和 CSR 在 Agent 的 `direct/<service-id>/` 保存；Server 仅保存 CSR、证书链和 ACME 账户。备份时同时保留两端数据目录，不应删除私钥文件来尝试修复网络问题。
- 直连响应体不经过 Server，不计入转发额度。转发额度耗尽不关闭已就绪的直连入口，但纯 IPv4 用户仍受转发额度限制。
- Agent Caddy 日志位于 Agent 数据目录的 `direct/caddy.log`。端口被 NAS 其他程序占用时需由部署者解决，不会接管已有程序。
- Emby 建议使用自身认证。Nexo 密码保护在两条路径都执行，原生客户端若不支持网页密码登录则不能绕过。双栈客户端的 IPv6 故障回退由客户端实现，不能保证播放中无感切换。

## 验证范围与真实网络验收

自动测试包含服务端口迁移/冲突/会话撤销、旧协议兼容、真实 mTLS/ALPN 隔离、模拟 DNS 提供商与本地 ACME/DNS-01、外部记录修改保护、AAAA 撤销、续期失败保留旧链、转发额度耗尽时直连状态、Agent 真实 Caddy 的 Range/206、上传、协议升级、授权拒绝、证书重载和已有连接撤销。Playwright 覆盖桌面、窄屏、横屏及 WebKit 的服务与域名表单。

本地 CA 和 DNS 桩验证协议与状态管理，不代表三家生产 API、真实公网证书或 NAS 入站网络已经验收。真实网络请使用独立测试域名，依次检查：

1. 纯 IPv4 网络访问同一 `https://主机名:端口`，确认仍走 Server；原管理入口和 443 服务正常。
2. IPv6 网络访问同一地址，检查实际远端是 NAS IPv6；执行 Emby 播放、拖动、上传、WebSocket 和长时间播放。
3. 关闭直连、变更端口或认证、断开 Agent，确认已有连接撤销、DNS 按记录所有权恢复、IPv4 转发继续可用。
4. 分别在手机和电视原生 Emby 客户端测试，包括 IPv6 部分不可达的网络。通过后再为已有服务启用。

本功能随 v0.2.9 发布，安装与更新见 [发布说明](releases/v0.2.9.md)。发布不会自动部署或为现有公网域名开启直连，NAS 真机验收需在具备对应环境后执行。
