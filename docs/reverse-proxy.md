# VPS 反向代理

## 场景走查

- 管理员没有 Agent：进入服务页点击「添加反向代理」，直接填写名称、目标协议/IP 或主机名/端口及公网域名，即可保存；首页不要求先安装 Agent。
- 编辑与停用：目标修改后更新 Caddy 路由，停用或删除后撤销入口；不下发 Agent 配置。
- 目标不可达：入口「已生效」只表示配置和公网证书就绪，实际请求返回网关错误，不宣称目标健康。
- 普通用户：在自己的工作空间管理反向代理。自己添加的节点经管理员审批、启用后即可使用；共享节点复用管理员的工作空间授权。内置节点需要管理员在节点配置中明确授权反代，原有穿透权限不变。
- 单节点回源：选择一个公网节点后，目标地址由该节点访问，`127.0.0.1` 表示该节点本机。授权意味着允许访问节点本机及其可达内网；无需 Agent，不支持节点组或多节点策略。
- 撤销授权：相关入口撤下，可停用、删除或迁移到另一个有权限的节点，不能重新启用无权限节点。旧节点须先升级到支持反代的版本。
- 混合选择：可启停或删除，不能批量修改 Agent；反代不进入穿透流量筛选，也不受穿透额度限制。

- 两个创建入口独立：「创建服务」只创建内网穿透，「添加反向代理」直接打开反代表单。手机端点击右下角「＋」后选择，桌面并列显示两个按钮。普通用户没有 Agent 时也可以进入反代表单；没有可选节点时需先获得审批、授权或升级节点。

## 配置

用户点击「服务 → 添加反向代理」，选择已授权的单个节点。例如目标 `HTTP / 127.0.0.1 / 3000`，公网入口 `HTTPS / app / example.com`，访问 `https://app.example.com` 即可。

官方 Linux Compose 使用宿主机网络，`127.0.0.1` 指 VPS 本机。其他容器可将应用端口发布到宿主机回环地址，然后填写该端口；自定义桥接部署需填写所选节点所在网络可达的容器地址，容器内的 `127.0.0.1` 不代表宿主机。

公网与目标协议独立。HTTPS 回源验证目标主机的证书，不支持自签名证书或跳过校验；同机应用可用 HTTP 回源。请求路径、查询参数及公网 Host 保留，支持 WebSocket。

服务模式创建后不可更改。反向代理不支持 TCP、内网重定向或绑定 Agent；本次不纳入穿透流量统计和额度。更换模式请重新创建服务。

## 接口兼容

服务仍使用 `/api/v1/tunnels`。请求与响应新增 `service_mode`（`tunnel` 或 `reverse_proxy`）；旧客户端创建时省略默认穿透，更新时省略保留原模式。反代通过 `origin_protocol`、`local_address`、`local_port` 指定目标，`device_id` 必须为空。

批量启停使用 `POST /api/v1/tunnels/batch/enable` 和 `/batch/disable`，批量删除使用 `DELETE /api/v1/tunnels/batch`，请求均为 `{"tunnel_ids":["服务 ID"]}`。先检查整批权限与归属，再事务提交；任一项校验失败均不修改本批配置。启停返回更新后的服务数组，删除返回 `deleted_ids`。单项接口保持兼容。

反代沿用 `apply_status` 字段，`ready` 表示路由及所需公网证书已生效，不是目标健康检查。回源连接失败时 Caddy 返回网关错误。

## 节点兼容与部署

独立节点反代需要已验证域名和 DNS 凭据，沿用业务子域名 A 的自动协调及外部修改保护；HTTPS 证书由控制器签发后仅分发给授权节点。切换节点时撤下旧入口并等待新入口就绪，DNS 缓存可能延迟切换。

节点接口返回 `reverse_proxy_supported` 和 `reverse_proxy_selectable`，前者表示直接回源能力，后者表示当前工作空间使用权限；审批、启用状态仍须同时满足。内置节点配置接口的 `workspace_ids` 仅表示明确的反代授权，不改变已有穿透权限。旧节点未声明支持时禁止创建或下发反代服务。

本功能涉及 Server 与独立节点运行代码，实际发布时分别更新这两个组件；Agent 无需更新。本次实现不执行部署或发布。
