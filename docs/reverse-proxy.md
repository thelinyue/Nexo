# VPS 反向代理

## 场景走查

- 管理员没有 Agent：进入服务页点击「添加反向代理」，直接填写名称、目标协议/IP 或主机名/端口及公网域名，即可保存；首页不要求先安装 Agent。
- 编辑与停用：目标修改后更新 Caddy 路由，停用或删除后撤销入口；不下发 Agent 配置。
- 目标不可达：入口「已生效」只表示配置和公网证书就绪，实际请求返回网关错误，不宣称目标健康。
- 普通用户：只能创建内网穿透；即使直接调用 API，也不能修改管理员创建的反向代理。
- 混合选择：可启停或删除，不能批量修改 Agent；反代不进入穿透流量筛选，也不受穿透额度限制。

- 两个创建入口独立：「创建服务」只创建内网穿透，「添加反向代理」直接打开反代表单；表单不再提供连接方式切换。手机端点击右下角「＋」后选择，桌面并列显示两个按钮。空列表也提供独立入口，普通用户不显示反代入口。

## 配置

管理员点击「服务 → 添加反向代理」。例如目标 `HTTP / 127.0.0.1 / 3000`，公网入口 `HTTPS / app / example.com`，访问 `https://app.example.com` 即可。

官方 Linux Compose 使用宿主机网络，`127.0.0.1` 指 VPS 本机。其他容器可将应用端口发布到宿主机回环地址，然后填写该端口；自定义桥接部署需填写 Nexo Server 所在网络可达的容器地址，容器内的 `127.0.0.1` 不代表宿主机。

公网与目标协议独立。HTTPS 回源验证目标主机的证书，不支持自签名证书或跳过校验；同机应用可用 HTTP 回源。请求路径、查询参数及公网 Host 保留，支持 WebSocket。

服务模式创建后不可更改。反向代理不支持 TCP、内网重定向或绑定 Agent；本次不纳入穿透流量统计和额度。更换模式请重新创建服务。

## 接口兼容

服务仍使用 `/api/v1/tunnels`。请求与响应新增 `service_mode`（`tunnel` 或 `reverse_proxy`）；旧客户端创建时省略默认穿透，更新时省略保留原模式。反代通过 `origin_protocol`、`local_address`、`local_port` 指定目标，`device_id` 必须为空。

批量启停使用 `POST /api/v1/tunnels/batch/enable` 和 `/batch/disable`，批量删除使用 `DELETE /api/v1/tunnels/batch`，请求均为 `{"tunnel_ids":["服务 ID"]}`。先检查整批权限与归属，再事务提交；任一项校验失败均不修改本批配置。启停返回更新后的服务数组，删除返回 `deleted_ids`。单项接口保持兼容。

反代沿用 `apply_status` 字段，`ready` 表示路由及所需公网证书已生效，不是目标健康检查。回源连接失败时 Caddy 返回网关错误。
