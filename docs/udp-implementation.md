# UDP 穿透实现与验收

## 使用场景与表单

创建远程桌面：选择 TCP+UDP、Agent、电脑内网 IP、3389 和公网端口 20023。保存后在详情分别查看 TCP 和 UDP；地址只复制，不作为网页链接打开。

UDP 被阻断：TCP 继续工作，列表显示“部分可用”，详情解释 UDP 数据通道未连接。UDP 恢复后自动重连，不要求重新保存。停用或删除服务同时撤销两种协议的既有会话。

```text
服务类型  [网页] [TCP] [UDP] [TCP+UDP]
Agent     [选择 Agent]
内网目标  [192.168.1.100] [3389]
公网端口  [20023，留空自动分配]
                         [保存服务]

远程桌面                           部分可用
公网地址  example.com:20023           复制
TCP       可用
UDP       检查中 · UDP 数据通道未连接
```

小屏表单类型选择自然换行，沿用现有列表与详情结构。UDP“可用”表示转发入口和通道已建立，不代表目标应用已响应。

## 验收边界

真实 RDP 必须检查 Windows 实际协商的传输协议，UDP echo 不能替代此项。空闲会话回收后不保证内网主动推送可达；客户端再次发送可建立新会话。公网防火墙须放行 9891/udp 和实际服务端口，TCP+UDP 服务同时放行同号 TCP/UDP。

正式发布及线上部署不在本次操作范围。

## 资源选择与测量

Windows 本机 Debug 构建，真实 Server/Agent、回环 QUIC 代理、64 字节 UDP echo。以下是保持指定数量会话后，逐会话请求的往返延迟，不是公网性能或满负载吞吐承诺。

| 活跃会话 | Server 工作集 MiB | Agent 工作集 MiB | 往返 P50 ms | P95 ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 25.14 | 15.08 | 0.55 | 0.55 |
| 32 | 25.41 | 17.2 | 0.53 | 0.6 |
| 128 | 26.36 | 23.73 | 0.54 | 0.65 |
| 512 | 29.66 | 50.16 | 0.55 | 0.65 |
| 1024 | 33.32 | 85.14 | 0.44 | 0.54 |

保留每条 Agent QUIC 连接最多 1024 会话的上限。每个接收会话最多排队 16 包，但不预分配这些包；已排队载荷共用 8 MiB 预算，避免 1024 份独立大队列。QUIC 收发缓冲各有 8 MiB 上限，分片重组内存另限 8 MiB、2 秒过期。Server 公网入口的待发送载荷使用进程共享 8 MiB 预算。每个 Agent 会话的本地 UDP 接收缓冲最多 65,536 字节，是会话数增加时主要的内存增量。

空闲期限为 5 分钟，双向有效数据都会刷新；QUIC 连接自身每 15 秒 keepalive、45 秒无响应超时，与单个应用会话的回收独立。资源超限丢弃新包，中文告警限频，不把拥塞无限累积为延迟。

## 协议和兼容性

服务接口增加 `udp`、`tcp_udp`，当前控制协议直接下发完整协议配置，不协商旧 Agent 的 UDP 能力或降级组合服务。QUIC 使用独立 ALPN `nexo-udp/1` 和现有设备证书，未启用 0-RTT。

Agent 仅在存在已启用的 UDP 或 TCP+UDP 服务时建立 QUIC 连接；停用最后一项 UDP 服务后关闭该连接，纯 TCP/网页服务无需额外 UDP 数据通道。

TCP、UDP 各自有公网端口唯一约束，组合服务同时占用两个命名空间。下一版本直接事务初始化完整结构，两端必须全新安装，不再执行历史数据升级。

UDP 计数按 Server 实际提交的应用载荷结算。整个数据报预算不足则不发送；如果提交部分分片后失败，只消费已经提交的字节。同步提交与 TCP 写入共用额度锁，无跨异步等待的预算占用。
