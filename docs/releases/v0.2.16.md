# Nexo v0.2.16

## 发布组件

- Server（含 Web 与 x86_64、ARM64 原生节点安装包）：`ghcr.io/thelinyue/nexo-server:0.2.16`。
- Agent 本次无运行时代码变化，不发布 `0.2.16` 镜像；Agent 最新正式版保持 `ghcr.io/thelinyue/nexo-agent:0.2.14`。共享协议新增字段仅用于 Server 节点健康报告，不影响 Agent 的消息处理。
- Docker 部署包仅包含 Server 的 Compose、配置、发布清单和许可证。

## 更新内容

- 域名新增“配置解析”：预览 DNS 服务商的主域名与泛域名记录，再确认写入 Server 公网 IPv4；接管 CNAME 或多条 A 记录需要确认。写入前复核地址、凭据、权限与已有记录，部分失败仅恢复本次已确认的改动，不覆盖外部修改。
- HTTPS 证书统一使用 DNS 验证，移除 HTTP 验证及隐式回退。升级保留域名归属验证、DNS 凭据和高级参数；已有 HTTP 验证域名转换为 DNS 验证，缺少凭据时无法新签发或续期，须在域名配置中补齐。仍有效的证书、HTTP 服务与 HTTP 跳转继续使用。
- 节点入口按实际 HTTP/HTTPS 协议检查指定公网 IPv4、Host、TLS 证书及服务配置版本；旧节点保持 TCP 兼容检查。健康状态按连续成功或失败收敛，地址或配置变化后重新检查，过期样本不能继续用于 DNS 发布或节点维护。
- 服务详情展示逐节点检查类型、时间和错误，区分失败、过期与待检查；IPv4 入口不可用时保留独立的 IPv6 直连状态。域名和服务页面补齐状态反馈与窄屏布局。

## 更新方式

本版本包含数据库结构与证书配置迁移。核对 Release 的原生节点包、Server Docker 部署包及 `SHA256SUMS`，停止 Server 后备份完整数据目录、Compose 与自定义配置（包括数据库、接入密钥、DNS 凭据、证书及节点身份）。保持原挂载、网络和环境变量，将 Server 镜像固定为 `0.2.16`，只重建 Server：

```bash
docker compose stop nexo-server
# 备份完整数据目录、Compose 和配置后，将 Server 镜像标签改为 0.2.16。
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

确认原账号、Agent 在线、DNS 凭据及既有服务可访问。Agent `0.2.14` 可与 Server `0.2.16` 配合使用，不替换 Agent 数据目录或身份。回退 Server 时先停止容器，恢复升级前镜像及完整数据、配置备份；不要让旧版本直接使用迁移后的数据库。

## 验证范围

自动化测试覆盖 DNS 预览确认、并发修改保护、权限隔离、部分失败恢复、配置迁移与入口探测，以及桌面、手机竖屏/横屏和 WebKit 界面。原生节点包由 Linux x86_64 与 ARM64 CI 分别构建；ARM64 实机安装、公网多节点故障切换及三家 DNS 服务商真实写入仍需对应环境验收。双栈 DNS 不保证客户端在 IPv6 失败后自动切换到 IPv4。
