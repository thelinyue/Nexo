# Nexo v0.2.13

## 发布组件

- Server（含 Web 与 x86_64、ARM64 原生节点安装包）：`ghcr.io/thelinyue/nexo-server:0.2.13`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.13`。
- 两端均有运行时代码变化。本次部署包包含两端的 Compose、TOML、发布清单和许可证。

## 改进与兼容

- 新增节点申请、凭证续领、注册、审批、工作空间授权、节点组和维护任务接口。Server 与原生节点使用独立身份及 mTLS/Yamux；Agent 增加节点能力通告、连接延迟和集中额度消息。管理员控制更新与分配，普通用户只能申请并查看本工作空间授权的节点。
- Server 为节点、服务分配、健康状态、DNS 协调和更新任务增量创建表与字段；已有服务默认使用内置节点，原 Server/Agent 数据目录和设备身份保留。升级前仍须备份数据库、身份、Compose 和自定义配置。
- 多节点服务仅将健康入口纳入 DNS A 记录；NAS IPv6 直连的 AAAA 独立维护。DNS 缓存及客户端重试决定切换时间，既有连接不保证无损迁移。所有参与同一服务的公网节点须提供相同访问端口。
- 流量历史查询、状态写入和 Caddy 配置检查减少无效工作；Web 按页面分包并提供 gzip 静态资源。性能对照数据是本地测量，不代表线上收益或容量保证。

## 更新

先确认 GitHub Release 中的两种架构节点包、Docker 部署包和 `SHA256SUMS` 完整，再分别备份两端数据目录、Compose 与自定义配置。保留挂载、网络、节点身份和现有环境变量，将原 Compose 中的镜像标签固定为 `0.2.13`，只拉取并重建对应服务：

```bash
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health

# Agent 原部署目录，按实际 Compose 文件名指定 -f
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
```

先确认管理登录、原 Agent 在线及既有服务可访问，再添加节点。原生节点安装命令由节点页生成，凭证只通过标准输入传入；节点需独立数据目录、公网 HTTPS 管理地址，以及业务入口和数据端口。不要用安装器替换现有 Docker Server。

回退时分别恢复原镜像标签及升级前的数据与配置备份，核对账号、设备身份和服务。已写入的新节点配置在旧版 Server 中不可用，不应靠反复重启旧镜像解决。正式域名证书、真实公网 DNS 切换、原生 systemd 更新/回退及 ARM64 实机仍需在发布后分项验收；本地及隔离测试结果见 [多节点开发验证](../multi-node.md)，不得当作正式环境通过记录。
