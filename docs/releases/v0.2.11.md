# Nexo v0.2.11

## 发布组件

- Server（含 Web）：`ghcr.io/thelinyue/nexo-server:0.2.11`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.11`。

两端均有实际代码变化。本版从 v0.2.10 更新无需数据库迁移，现有数据目录、设备身份和服务配置继续使用。

## 改进与修复

- 服务器设置新增手动公网 IPv4，保存后用于转发入口和 DNS A 记录；不探测公网 IPv4。
- Agent 自动选择可用公网 IPv6，原地址有效时保持不变，地址变化后重新确认直连就绪并更新 Nexo 管理的 AAAA 记录。
- IPv6 直连复用 Server 已签发的相应域名泛域名证书。更换同一泛域名覆盖的主机名无需单独签发；证书尚未就绪时明确报错。Server 与 Agent 均须更新至本版才能使用复用流程。
- 修复带查询参数的 Emby 资源被直连认证请求误拦截，导致首页停在启动画面的问题。
- Server 启动时等待 Caddy 管理接口就绪，避免正常启动短暂显示“配置加载失败”。两端日志显示本地时区。
- 服务列表公网地址的复制按钮紧跟链接。

## 更新

更新前备份 Server 与 Agent 的完整数据目录、Compose 和自定义 TOML。保留现有挂载和节点身份，只修改对应 Compose 文件中的镜像标签为 `0.2.11`，然后分别执行：

```bash
# Server 原部署目录
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health

# Agent 原部署目录，按实际 Compose 文件名指定 -f
docker compose -f docker-compose.yml pull nexo-agent
docker compose -f docker-compose.yml up -d --no-deps nexo-agent
```

检查 Agent 在线、既有服务访问、IPv6 直连 Emby 登录页和带查询参数的脚本请求。若回退，恢复原镜像标签及更新前完整数据备份。VPS 无 IPv6 出站时，Server 的公网探测状态仍可能显示“未验证”；这不表示直连入口不可用。
