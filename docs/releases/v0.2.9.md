# Nexo v0.2.9

## 发布组件

- Server（含 Web）：`ghcr.io/thelinyue/nexo-server:0.2.9`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.9`。

相对上一正式版 v0.2.8，两端及共享协议均有实际代码变化。部署包包含两端模板，镜像固定为 `0.2.9`。

## 改进与修复

- HTTPS 穿透和反向代理支持自定义公网端口，访问地址、复制、跳转及授权同步使用所选端口；不同端口的 Caddy 路由相互隔离，管理入口保持原端口。
- 可选 IPv6 直连由 Agent 本地 Caddy 提供 HTTPS，私钥保留在 Agent；通过独立 mTLS 管理连接获取证书与集中授权。A 记录指向 Server，AAAA 指向 Agent，纯 IPv4 客户端继续使用原转发通道。
- DNS 验证支持 Cloudflare、阿里云 DNS、腾讯云 DNSPod，提供记录冲突检查、外部修改保护、AAAA 撤销和失败重试。有效旧证书在续期失败时继续使用。
- 精简域名列表、详情和日志入口；DNS 解析器留空时使用 Caddy 默认值，已保存的自定义值保持不变。转发 IPv4 统一在 Server TOML 的 `direct.relay_ipv4` 配置。
- 关闭直连、变更配置或控制连接失效会撤销 Agent 入口及已有连接；直连响应流量不计入 Server 转发额度，转发额度耗尽不关闭已就绪的直连入口。

## 安装与更新

已有 v0.2.5 至 v0.2.8 实例可保留数据与身份。Server 启动时增量补充 HTTPS 端口、DNS 提供商及直连所需字段与表；已有服务默认端口 443、直连关闭。仅使用自定义 HTTPS 端口无需升级旧 Agent；启用 IPv6 直连必须两端使用 v0.2.9。稳定公网 IPv6 自动发现目前面向 Linux/NAS。

更新前停止并备份完整数据目录、TOML 和 Compose，保留现有挂载和自定义配置，再将需要更新的组件镜像标签改为 `0.2.9`：

```bash
# Server 主机，原部署目录
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
docker compose logs --tail=100 nexo-server

# Agent 主机，原部署目录；按实际文件名使用 -f
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
docker compose -f compose.agent.yml logs --tail=100 nexo-agent
```

已有 Agent 不要执行新增设备配置，也不要更换数据目录。检查 Server `/health`、登录、Agent 在线及既有服务访问。回退时停止新组件，使用原版本镜像及更新前完整备份。从 v0.2.4 及更早版本安装仍要求两端使用独立空数据目录，不导入旧数据库或身份。

启用直连前配置 `direct.relay_ipv4`、域名 DNS 验证凭据及 NAS 稳定公网 IPv6，放行业务 TCP 端口。Nexo 不修改主机防火墙或容器端口映射。已有 DNS 冲突需先核对，不能自动接管外部记录。使用独立测试域名，按 [HTTPS 端口与 IPv6 直连说明](https://github.com/thelinyue/Nexo/blob/v0.2.9/docs/https-ipv6-direct.md) 完成验收后再为已有服务开启。
