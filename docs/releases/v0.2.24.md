# Nexo v0.2.24

## 发布组件

- Server：`ghcr.io/thelinyue/nexo-server:0.2.24`，包含 Web 首页、统计接口、增量数据库迁移及内置入口采集。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.24`，增加 IPv6 直连入口访问统计上报。
- 独立节点：`0.2.24`，提供 Linux x86_64 / ARM64 原生包，增加访问与会话统计上报。
- 三个组件均有运行代码变化；节点版本从最近实际发布的 `0.2.21` 更新为 `0.2.24`。只升级实际需要的服务，保留原数据目录和身份。

## 更新内容

- 首页参考 HP-Lite 的信息布局，增加请求数、双向流量、延迟、QPS、状态分布、来源与服务排行、请求流及单服务详情；沿用 Nexo 的空间权限与主题。
- Caddy 完成日志采集 HTTP/HTTPS/WebSocket，TCP/UDP 按成功转发字节计量；支持实时与历史筛选、请求/会话分页、暂停、键盘读数、小屏布局和采集缺口提示。
- 内置入口、独立节点与 Agent 直连使用有界队列和事件主键去重；控制器根据认证身份与服务授权确定归属。天眼不替代原有流量与额度账本，重置用量不会删除天眼历史或恢复额度。
- 请求/会话明细保留 7 天，小时聚合保留 90 天。只保存来源网段，剔除查询参数、认证头、Cookie 和请求体；持久化 `analytics.key` 保持同一天的近似访客标识。
- 可选本地 Country/ASN MMDB；未配置、缺失或损坏时显示未知，不向外部服务查询访客 IP。测试数据库不随产品分发。
- 修复隔离冒烟脚本的 DNS、测试 CA、自定义 HTTPS 端口与响应夹具。测试注入仅存在于 Rust 测试程序，不向正式二进制增加绕过开关。

统计语义、复现命令与验证边界见 [流量天眼](../traffic-eye.md)。HTTP 统计为请求完成时的应用层数据量，不能当作精确链路计费；WebSocket 在连接结束后出现。长周期访客数为每日近似去重数之和，p50/p95 使用延迟桶上界。

## 更新与回退

先停止待更新组件，备份完整数据目录、Compose 与配置，包含 SQLite 数据库、证书、密钥、身份和图标。Server 启动会增量创建 `analytics_*` 表，不补算升级前未采集的历史访问；升级后备份还须包含 `analytics.key`。

将 Compose 中需要更新的镜像固定为 `0.2.24`，保留现有挂载、网络和环境变量。管理 VPS 只有 Server 时：

```bash
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

Agent 在其实际部署机器上独立更新 `nexo-agent`，不重建身份；原生节点通过现有节点更新功能或安装/更新助手升级，不应因管理端更新直接重装节点。旧 Agent/节点可继续转发，但不能据此声明新增远端统计已覆盖；需升级相应入口才能验收其统计上报。

回退时停止受影响组件，恢复原镜像或节点程序及升级前完整数据/配置备份，再启动。不要将旧数据库与新证书、密钥或身份目录混用。生产验证应分别核对升级前在线业务、认证边界、真实请求产生的统计增量和页面运行版本；离线入口与公网 IPv6 链路需单独验证。

## 验证范围

本地已有真实 Caddy、Server/Agent 穿透、独立节点、IPv6 回环统计上报及 MMDB 验证；IPv6 回环入口授权仍为测试夹具，不等同于公网 AAAA 发布和完整外网认证链路。UDP 覆盖 1/5/15 分钟真实空闲及恢复，不等同于真实 RDP 客户端验收。

正式发布还需以当前提交的 CI、双架构节点包、容器镜像、公开资产校验及实际生产升级结果为准，不用历史本地结果替代本次发布验收。
