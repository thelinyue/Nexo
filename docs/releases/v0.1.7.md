# Nexo v0.1.7

Nexo `v0.1.7` 将公网入口从单一域名扩展为多域名资源，并把证书生命周期、Caddy 自动退避和主域名迁移状态完整呈现在 Web 管理界面。

## 主要变化

- 域名与 HTTPS 页面支持一个主域名和多个附加域名；每个域名可独立使用 Cloudflare DNS-01 或手动证书。
- 域名列表支持全选、批量重新检测、批量申请证书；单域名提供手动申请按钮。
- 根证书和泛域名证书分别显示状态、SAN、到期时间和 Caddy 预计进入续期窗口的时间。
- CA 返回 429 时显示 Retry-After、尝试次数和下次重试时间，申请按钮在限流窗口内禁用；不创建与 Caddy 竞争的 ACME 重试器。
- Caddy storage 固定在 `/data/nexo/caddy-storage`，Cloudflare Token 和手动证书按域名隔离保存并设置受限权限。
- 主域名切换保留旧入口直到设备 ACK 完成；删除被服务引用的域名必须先选择已 READY 的替代域名。

## Caddy 与 Headscale 约束

- Caddy 使用官方 Automatic HTTPS、DNS-01 和自身指数退避；“手动申请证书”只触发配置协调，不绕过 CA 限流。
- `mesh.<domain>` 必须在 Cloudflare 中设置为 DNS only。Nexo 只检测 DNS、TLS 和代理迹象，不自动修改 DNS。
- Headscale 反向代理保留 POST、长连接和 `Upgrade: tailscale-control-protocol`，只信任本机回环代理。

## 升级

升级前停止 `nexo-server`，备份 `/opt/stacks/nexo/compose.yml` 和完整 `/opt/stacks/nexo/data/nexo`。如果旧版本使用宿主机 Caddy，先把 `/root/.local/share/caddy` 原样复制到 `data/nexo/caddy-storage`，再启动新 Server。数据库迁移会自动执行；回滚必须同时恢复数据备份和旧镜像。

正式部署使用 `ghcr.io/thelinyue/nexo-server:0.1.7` 和 `ghcr.io/thelinyue/nexo-agent:0.1.7`。发布工作流会在本节后附加镜像 digest 与部署包校验和。
