# Nexo v0.2.8

## 发布组件

- Server（含 Web）：`ghcr.io/thelinyue/nexo-server:0.2.8`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.8`。

v0.2.7 标签已存在，但发布任务被取消、未创建正式 Release；本版包含其原生 Agent 部署修复。相对上一正式版 Server v0.2.6 / Agent v0.2.5，两端均有实际代码变化。部署包包含两端模板，镜像固定为 `0.2.8`。

## 改进与修复

- 服务器设置可选择自己空间内已验证并开启 HTTPS 的域名，内置 Caddy 自动添加管理入口、复用证书并强制 HTTPS，无需手动创建反向代理服务或填写可信代理 IP。
- 保留原 IP 管理入口，允许证书或代理异常时修正设置；该入口仍为明文，应限制公网可达范围。HTTPS Cookie、管理员权限、Origin 和 CSRF 检查继续生效。旧手工代理安全规则保留到管理员显式保存新设置。
- 新建 HTTPS 反向代理默认强制 HTTPS，可关闭；307 跳转保留方法、路径与查询参数且不缓存。旧服务默认关闭，不自动改变访问行为。
- 完善服务表单布局、手机添加入口、管理入口状态反馈和失败草稿保留。
- Agent 页面直接提供原生 Compose YAML 或单条 docker run 命令。Agent 支持三个非空连接环境变量逐项覆盖 TOML，不回写文件；空值回退，身份恢复仍使用专用命令行凭证，已有身份继续复用。

## 发布前验证

- Rust 格式、Clippy（禁止警告）与 workspace 构建通过；常规测试 127 项通过，真实 Caddy 5 项单独执行通过。
- Web 构建通过；桌面、移动 Chromium 和移动 WebKit 回归 562 项通过、86 项按平台或视口跳过。
- 真实剪贴板 9 项通过；WebKit 的 3 项因权限接口不支持跳过。
- 真实 Agent 配置、接入及身份复用 10 项通过；账号恢复、设备恢复、TCP 转发和来源保护 9 项通过；latest 发布规则 10 项通过。

## 安装与更新

已有 v0.2.5 / v0.2.6 / v0.2.7 实例可保留数据与身份。Server 启动时为现有服务表补充 `http_redirect_enabled` 字段，默认关闭；通信协议未改变。更新前停止并备份完整数据目录、TOML 和 Compose，保留现有挂载和自定义配置，再将对应镜像标签改为 `0.2.8`：

```bash
# Server 主机，原部署目录
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
docker compose logs --tail=100 nexo-server

# Agent 主机，原部署目录；按实际文件名使用 -f
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
docker compose -f compose.agent.yml logs --tail=100 nexo-agent
```

已有 Agent 不要执行新增设备配置，也不要更换数据目录。旧 Agent 可继续使用 TOML 连接；使用页面生成的环境变量部署配置时，请使用本版 Agent。检查 Server `/health`、登录、Agent 在线及既有服务访问。回退时停止新组件，使用原版本镜像及更新前完整备份。

从 v0.2.4 及更早版本安装仍要求两端使用独立空数据目录，不导入旧数据库或身份。新安装见 [项目说明](https://github.com/thelinyue/Nexo/blob/v0.2.8/README.md)，参数和备份见 [容器文档](https://github.com/thelinyue/Nexo/blob/v0.2.8/docker/README.md)。

本次发布不自动更新现有 VPS 或 Agent 部署。公网 DNS / Cloudflare DNS-01、公共 ACME、真实 NAS 管理界面、手机系统剪贴板及长时负载不属于本次验收结论。
