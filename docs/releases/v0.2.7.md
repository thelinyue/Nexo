# Nexo v0.2.7

## 修复

- 添加 Agent 的 Compose 选项直接给出原生 YAML，可粘贴到 NAS Compose 项目或保存为 `compose.agent.yml`。
- docker run 选项直接给出一条启动命令。两种方式都内嵌 Server 地址、接入密钥和设备名称，不包含 Shell 安装脚本，也不要求单独保存 TOML。
- Agent 支持 `NEXO_SERVER_URL` / `NEXO_ENROLLMENT_TOKEN` / `NEXO_DEVICE_NAME`：非空值逐项覆盖 TOML，空值回退，环境变量不回写文件。显式身份恢复继续使用命令行专用凭证。
- 原 TOML 配置继续可用；已有设备身份不会被覆盖，接入后清空接入密钥仍可重启。Compose 的 `$` 插值与 Shell 特殊字符分别正确转义。

## 发布组件

- Server（含 Web）：`ghcr.io/thelinyue/nexo-server:0.2.7`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.7`。

两端均有实际代码变化。本版页面生成的环境变量配置要求 Agent v0.2.7；旧 Agent 仍可使用已有 TOML 连接新版 Server。部署包包含两端模板，镜像固定为 `0.2.7`。

## 更新

已有 v0.2.5 / v0.2.6 实例可以保留完整数据目录和身份，本次没有数据库或通信协议变化。停止并备份对应组件的数据与 Compose，保留现有挂载和自定义配置，仅修改对应镜像标签后拉取、重建：

```bash
# Server 主机，原部署目录
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server

# Agent 主机，原部署目录；按实际文件名使用 -f
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
```

已有 Agent 不要执行新增设备配置，也不要改换数据目录。更新后检查 Server `/health`、登录、Agent 在线状态及既有服务访问；回退时停止新组件，使用原版本镜像和更新前完整备份。

从 v0.2.4 及更早版本安装仍要求两端使用独立空数据目录，不导入旧数据库或身份。新安装见 [项目说明](https://github.com/thelinyue/Nexo/blob/v0.2.7/README.md)，参数与备份见 [容器文档](https://github.com/thelinyue/Nexo/blob/v0.2.7/docker/README.md)。

配置含接入密钥，Docker 管理员可通过容器信息查看；请勿分享，接入成功后可清空该密钥，保留 Server 地址和原数据目录。本次发布不自动更新现有 VPS 或 Agent 部署。公网 DNS、公共 ACME、真实 NAS 管理界面与长时负载不属于本次验收结论。
