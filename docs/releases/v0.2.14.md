# Nexo v0.2.14

## 发布组件

- Server（含 Web 与 x86_64、ARM64 原生节点安装包）：`ghcr.io/thelinyue/nexo-server:0.2.14`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.14`。
- 两端均有运行时代码变化；本次部署包包含两端的 Compose、TOML、发布清单和许可证。

## 改进与兼容

- 普通 Yamux Tunnel 数据连接在 Server 和 Agent 两端启用 TCP_NODELAY，减少小帧等待；控制连接、其他 ALPN、心跳、额度和协议保持原行为。两端混搭的恢复验收已通过，仍建议分别升级并确认 Agent 重新在线。
- 首页改为更紧凑的流量概览和关注事项，历史曲线按实际时间及采集缺口绘制；节点页整理列表、详情、筛选和维护操作。桌面导航、手机 PWA 顶栏及更多菜单调整了入口与焦点行为。
- 配对性能测量完成 36/36 轮，功能和额度校验通过；具体数据、波动及适用边界见 [TCP_NODELAY 测量](https://github.com/thelinyue/Nexo/blob/v0.2.14/docs/performance-nodelay-2026-09-30.md)。本地测量不代表线上吞吐或时延保证。
- 本次无数据库迁移，保留原 Server/Agent 数据目录和设备身份。

## 更新

先核对 GitHub Release 中两种架构节点包、Docker 部署包及 `SHA256SUMS`，再分别停止对应容器并备份完整数据目录、Compose 与自定义配置。保持原挂载、网络、身份和环境变量，将两端各自的镜像标签固定为 `0.2.14`，只拉取并重建对应服务：

```bash
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health

# Agent 原部署目录，按实际 Compose 文件名指定 -f
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
```

升级后核对 Server 健康、Agent 在线、原有服务转发及设备身份。回退时分别恢复原镜像标签与升级前的完整数据和配置备份。真实公网客户端与 NAS/VPS 链路仍需部署后验收。
