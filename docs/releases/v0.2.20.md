# Nexo v0.2.20

## 发布组件

- Server（含 Web 与数据库迁移）：`ghcr.io/thelinyue/nexo-server:0.2.20`。
- 独立节点：提供 Linux x86_64、ARM64 原生安装包，节点版本为 `0.2.20`。
- Agent 没有实际代码变化，不发布新镜像或部署包，不需要升级。

## 更新内容

- 普通用户可以在自己的工作空间创建反向代理，选择自己添加且已由管理员审批启用的节点，或者管理员通过工作空间、节点组授权的节点。
- 内置节点的反向代理授权单独管理，不改变原有隧道权限；已有内置反向代理工作空间在首次迁移时保留授权，后续撤销不会在重启时恢复。
- 反向代理采用手动选择的单个节点，无需 Agent。独立节点支持 HTTP/HTTPS 直接回源，保留 Host、路径、查询参数、证书验证、访问密码与 HTTPS 跳转；权限撤销后立即拒绝后续请求。
- 旧节点未声明反向代理能力时不会出现在新建反向代理的可选节点中。升级到本版后才支持该能力。
- 独立节点按实际代码变化发布，后续仅 Web 或管理端更新将保留独立节点版本。

## 更新和回退

升级前停止 Server，备份完整数据目录、Compose 与自定义配置。本版启动时增量创建内置反向代理授权表及授权视图；保留账号、设备身份和现有服务。

保留原挂载、网络与环境变量，将 Server 镜像标签固定为 `0.2.20`，仅更新 Server：

```bash
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

Compose 不在当前目录时使用 `-f <文件路径>`。确认 Server 健康、现有 Agent 重新连接、设备身份与服务绑定保留。Agent 无需拉取或重建。回退时停止 Server，恢复原镜像、Compose 与完整数据备份。

需要在独立节点创建反向代理时，核对节点包和 `SHA256SUMS` 后，通过节点页面的更新任务或现有更新助手升级到 `0.2.20`。保留节点身份和配置，升级后确认节点上线并具备反向代理能力。未升级的节点可继续使用原有隧道服务。

## 验证范围

已覆盖普通用户权限、内置节点显式授权、权限撤销与重新启用、旧节点兼容、节点直接回源，以及桌面和移动端创建流程。Server 回归包含真实 Caddy HTTP/HTTPS、密码、跳转和配置更新测试。正式发布由 CI 构建 Server 镜像与两种架构节点包。

移动浏览器仿真不代表真机验收；ARM64 实机、生产环境新建反向代理与公网 DNS 链路不属于本次自动化验收范围。
