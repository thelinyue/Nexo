# Nexo v0.2.23

## 发布组件

- 仅发布 Server：`ghcr.io/thelinyue/nexo-server:0.2.23`。
- Agent 与独立节点运行逻辑、节点协议、Caddy 和安装/更新助手无变化，不生成本版本镜像或节点包。独立节点版本保持 `0.2.21`，内置节点随 Server 更新。
- 无数据库迁移或新增公共 API。

## 更新内容

- 修复单个独立节点反代配置就绪后，客户端仍缓存管理端旧 IP 时返回 404 的问题。管理端旧入口转发到当前绑定节点的 IP 和服务端口，保留 Host、方法、路径、请求体和 WebSocket；精确 DNS 继续指向节点，正常流量保持直达。
- HTTPS 回源使用业务域名作为 SNI，并严格验证节点证书，避免重新解析业务域名形成循环。兼容路由逐请求检查当前绑定、配置版本、授权、节点健康、维护状态及节点额度；未就绪返回中文 503，撤权、停用或删除后阻断旧路由，未知域名仍返回 404。
- 复用现有密码页、登录限流与认证流程；管理端兼容检查保留 Cookie，由最终节点完成业务认证与 Cookie 清理。兼容路由撤销或切换时关闭旧 WebSocket 连接；即使管理端新配置加载失败，旧配置也不能继续按过期授权转发。

兼容路径会消耗管理端带宽，应用可能看到管理端作为直接来源。本次不增加代理信任配置，只兼容管理端旧入口，不覆盖任意历史节点 IP 或穿透服务，也不改变 DNS 选择、证书签发流程和节点额度计量。

## 更新和回退

升级前停止 Server，备份完整数据目录、Compose 与自定义配置，包括数据库、共享图标、证书存储、密钥与节点身份。保留原挂载、网络与环境变量，将 Server 镜像固定为 `0.2.23`，仅更新 Server：

```bash
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

Compose 不在当前目录时使用 `-f <文件路径>`。确认 Server 健康、Agent 与节点重新连接，并固定业务域名分别访问管理端 IP 和当前节点 IP，核对业务响应。Agent 与独立节点无需重建。

回退时停止 Server，恢复原镜像、Compose 与升级前完整数据备份，再启动 Server。

## 验证范围

Rust 工作区测试、格式检查与 Clippy 通过。四项真实 Caddy 集成测试已实际运行，覆盖管理端旧 IP 与节点直达、HTTP/HTTPS、SNI 与严格证书校验、密码登录、Cookie、POST、WebSocket、伪造内部元数据、撤权、换节点、额度耗尽与恢复，以及旧配置加载失败后的阻断。

集成测试使用本机 Caddy 与测试 CA，不代表客户端 DNS 缓存时间缩短；生产升级需另行验证实际域名两种入口。
