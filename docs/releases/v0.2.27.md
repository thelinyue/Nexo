# Nexo v0.2.27

## 发布组件

- Server（含管理界面）使用 `ghcr.io/thelinyue/nexo-server:0.2.27`。
- Agent 使用 `ghcr.io/thelinyue/nexo-agent:0.2.27`。
- 独立 VPS 节点提供 Linux x86_64 与 ARM64 原生包。

## 更新内容

- 流量天眼默认下载 DB-IP Country Lite 并使用最近一次有效缓存。仍可指定本地 Country 或 ASN MMDB，访客 IP 在采集进程内完成查询。[流量天眼](../traffic-eye.md)
- 内网穿透可按服务启用隧道压缩，默认关闭。入口节点与 Agent 协商支持后才使用压缩，旧端继续常规转发。TCP+UDP 服务只压缩 TCP 部分，计量沿用应用层字节数。[隧道压缩说明](../usage.md#隧道压缩)
- 独立 VPS 节点使用专用静态程序，可通过现有节点更新流程保留身份和数据。Server 同步更新管理界面、SQLite 与 DNS 解析库，三端使用 Caddy 2.11.9。

## 升级与回退

升级前停止待更新组件，备份现有 Compose、配置与完整数据目录，包括数据库、证书、密钥和身份。Server 首次启动会为已有数据库增加压缩开关字段，已有服务默认关闭压缩。

将所需镜像固定到 `0.2.27`，沿用原有挂载、网络及环境变量。分别在 Server 和 Agent 的部署主机执行对应服务的更新。

```sh
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
docker compose exec -T nexo-server nexo --version
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

```sh
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
```

独立节点可从管理界面的节点更新入口逐个升级。升级后检查设备与节点连接、现有服务入口和转发。需要回退时停止受影响组件，恢复相应的原镜像或节点程序、配置和配套数据备份，再启动组件。
