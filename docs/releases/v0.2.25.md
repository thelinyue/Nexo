# Nexo v0.2.25

## 发布组件

- Server：`ghcr.io/thelinyue/nexo-server:0.2.25`，包含 Web、服务级回源证书配置及数据库增量迁移。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.25`，支持按服务跳过 HTTPS 回源证书验证。
- 独立节点运行代码没有变化，不发布节点包；最近实际节点版本仍为 `0.2.24`。

## 更新内容

- HTTPS 内网穿透默认继续使用 Agent 的系统信任库；可按服务配置自定义 PEM 公钥证书，不修改设备系统信任库。
- 无法配置信任证书时，可对单个服务明确选择「跳过验证（不安全）」，无需上传 CA。这保留回源 HTTPS 加密，但不能验证服务身份，中间人可能窃取登录凭据。优先使用可信证书，并为管理后台启用多因素认证。
- 该设置不影响公网 HTTPS 证书或 Agent 与 Server 之间的 mTLS。切换到非 HTTPS 回源后保存会清除跳过验证选项；之后重新使用 HTTPS 时须再次明确选择。
- 服务详情显示内网证书验证关闭的风险，以及内置节点的回源错误；批量更换设备时提示 Agent 版本兼容性。

## 更新与回退

升级前备份 Server 和 Agent 各自完整数据目录、Compose 与配置，保留数据库、证书、密钥和 Agent 身份。只更新 Server 与需要此功能的 Agent，保留既有挂载、网络和设备身份，不重装独立节点。

先升级 Server，再升级相关 Agent；旧版 Agent 不支持「跳过验证」，选择该选项会导致其无法回源。更新后编辑服务，设定 HTTPS 内网协议并明确选择所需验证方式，检查服务状态和公网访问；PVE 等应用还需分别验证登录和控制台 WebSocket。

回退时停止受影响组件，并以配套的旧镜像、升级前完整数据和配置备份恢复。不要将旧数据库与新证书、密钥或身份目录混用。

## 验证范围与限制

本地测试覆盖系统信任、自定义 CA、显式跳过验证、TLS 1.2/1.3 签名和 WebSocket 帧，以及服务配置和界面交互。浏览器用例采用模拟接口，不替代真实 PVE 验收。

服务创建或编辑时会检查设备配置快照大小；在同一设备累积大量自定义 CA 且接近控制帧上限时，后续节点或启停变更仍可能导致快照超限并影响该设备服务。单服务选择跳过验证不需要添加 CA。具体使用方式和风险见 [使用说明](../usage.md)。
