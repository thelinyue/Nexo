# Nexo v0.2.18

## 发布组件

- Server（含 Web 与 x86_64、ARM64 原生节点安装包）：`ghcr.io/thelinyue/nexo-server:0.2.18`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.18`。
- 两端均有实际运行时代码变化，Docker 部署包包含两端的 Compose、配置、发布清单和许可证。

## 更新内容

- 服务支持批量修改根域名，保留主机名、回源、端口、认证、图标和节点选择；逐项读取最新配置，显示新旧地址及部分失败，已成功项不重复提交。
- 编辑服务按回源、公网入口和 IPv6 直连分别更新检查状态。名称、图标、认证、重定向或节点选择变化不清空无关链路的健康样本；保留样本的原检查时间，仍要求当前配置、节点加载确认和有效授权。
- Agent 对编辑推送只检查变化的回源，定期检查继续覆盖全部服务；异步检查完成时复核目标与 TLS 配置，避免旧目标的成功结果被用于新配置。
- 设备版本提示按官方正式 Release 与组件清单判断，Server 独立发布不会误报 Agent 更新；版本查询失败明确提示，开发版和缺失版本不误判。
- 调整账号菜单、登录会话和管理员设置入口，完善桌面、移动端及 PWA 导航、添加按钮、设备卡片与表单；统一面向用户的设备、客户端、服务端和隧道文案。

## 更新方式

从 Server `0.2.17`、Agent `0.2.14` 更新可保留现有账号、服务、配置和设备身份。本版本不新增数据库结构迁移。更新前核对 Release 的部署包、原生节点包及 `SHA256SUMS`，分别停止对应容器并备份完整数据目录、Compose 和自定义配置；不要清空数据目录或重新注册设备。

保持原挂载、网络和环境变量，先将 Server 镜像固定为 `0.2.18` 并重建：

```bash
docker compose stop nexo-server
# 备份完整数据目录、Compose 和配置后，将 Server 镜像标签改为 0.2.18。
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

再在 Agent 主机备份后，将 Agent 镜像固定为 `0.2.18` 并重建：

```bash
docker compose stop nexo-agent
# 备份完整数据目录、Compose 和配置后，将 Agent 镜像标签改为 0.2.18。
docker compose pull nexo-agent
docker compose up -d --no-deps nexo-agent
```

两端 Compose 文件位于不同目录时，分别使用 `-f <文件路径>`。确认 Server 健康、原设备身份和服务绑定保留、Agent 在线、控制与数据通道恢复，并检查既有服务访问。需要回退时停止对应容器，恢复原镜像、Compose 和完整数据备份。

## 验证范围

自动化验证覆盖服务更新后的健康样本保留与失效、过期结果拒绝、认证撤销、批量域名修改的权限及配置保留、设备版本查询，以及桌面、手机竖屏、横屏和 WebKit 交互。Rust 使用与 CI 一致的 `1.89.0` 工具链；原生节点包由 Linux x86_64 与 ARM64 CI 分别构建。

浏览器移动仿真不代表真机验收；ARM64 实机安装、长时高负载、公网多节点故障切换及所有 DNS 服务商的真实写入仍需对应环境验收。双栈 DNS 不保证客户端在 IPv6 失败后自动切换到 IPv4。
