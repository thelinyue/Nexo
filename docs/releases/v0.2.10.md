# Nexo v0.2.10

## 发布组件

- Server（含 Web）：`ghcr.io/thelinyue/nexo-server:0.2.10`。
- Agent：`ghcr.io/thelinyue/nexo-agent:0.2.10`。

相对上一正式版 v0.2.9，Server、Agent 及共享控制通道诊断均有实际代码变化。部署包包含两端模板，镜像固定为 `0.2.10`。

## 改进与修复

- 修复 IPv6 直连证书签发出现 `Cannot issue for "rcgen self signed cert"`：新 CSR 仅包含服务 SAN，Agent 保留原私钥自动重新生成已保存的错误 CSR；Server 拒绝 CN 与服务主机名不符的请求，避免继续提交无效订单。
- 修复已有反向代理配置时，状态刷新与 Caddy 事件写入因锁顺序冲突导致的启动死锁。该故障可能表现为日志显示已监听，但管理页面与 `/health` 一直无响应。
- 读取域名运行状态前释放数据库锁；回写状态时核对配置版本和删除状态，避免旧快照覆盖等待期间的新配置。
- Server 与 Agent 控制通道报错附带设备、对端地址、最后收发时间、距今间隔与消息数量，便于定位 45 秒心跳超时。日志不记录证书、凭据或消息正文；发送成功仅表示本地写入与 flush 完成。
- Caddy 日志区分证书处理、TLS 握手、HTTP 请求和运行错误；代理 EOF、断管、连接重置及普通 HTTP 429 不再误报为证书错误或 CA 限流。

## 安装与更新

已有 v0.2.5 至 v0.2.9 实例可保留数据与身份。本版相对 v0.2.9 不修改数据库结构、控制协议或心跳及重连策略。Server 死锁修复可独立更新；修复 IPv6 直连证书请求必须将 Agent 更新至 v0.2.10，已有错误请求会自动修复并重新申请，无需删除身份、私钥或服务。启用直连需要 Server 至少 v0.2.9，建议两端更新至本版。

更新前停止并备份完整数据目录、TOML 和 Compose，保留现有挂载和自定义配置，再将需要更新的组件镜像标签改为 `0.2.10`：

```bash
# Server 主机，原部署目录
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
docker compose logs --tail=100 nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health

# Agent 主机，原部署目录；按实际文件名使用 -f
docker compose -f compose.agent.yml pull nexo-agent
docker compose -f compose.agent.yml up -d --no-deps nexo-agent
docker compose -f compose.agent.yml logs --tail=100 nexo-agent
```

使用 `nexo-server:0.2.9-vps-fix.1` 临时修复镜像的实例，更新前将 Compose 镜像改为 `ghcr.io/thelinyue/nexo-server:0.2.10`，其余数据挂载和配置继续保留。

已有 Agent 不要执行新增设备配置，也不要更换数据目录。检查 Server `/health`、登录、Agent 在线及既有反向代理和穿透服务访问。回退时停止新组件，使用原版本镜像及更新前完整备份；存在反向代理启动死锁的实例应保留已验证的临时修复镜像用于回退。从 v0.2.4 及更早版本安装仍要求两端使用独立空数据目录，不导入旧数据库或身份。

本次发布不自动更新现有 VPS 或 Agent 部署，也不自动开启 IPv6 直连。
