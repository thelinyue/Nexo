# Nexo v0.2.22

## 发布组件

- Server（含 Web 与数据库迁移）：`ghcr.io/thelinyue/nexo-server:0.2.22`。
- 独立节点运行代码、Caddy 与安装/更新助手无变化，保持节点版本 `0.2.21`，不生成本版本节点包或升级指引。节点更新流程修复位于 Server 管理端。
- Agent 的协议与运行逻辑无变化，不发布新镜像或部署包，已有 Agent 保持原版本。

## 更新内容

- 服务页默认采用列表，可切换到图标视图并由本浏览器记住选择；切换保留搜索、筛选和多选，兼容手机竖屏与横屏。
- 公网入口展示 Nexo 最近确认的 IPv4 DNS 记录及其节点，区分已同步、待同步和同步失败；不会把健康候选当成已发布入口。IPv6 直连单独标识，DNS 缓存和现有连接仍可能影响客户端实际入口。
- 服务支持上传 PNG、JPG、WebP 或导入 HTTP/HTTPS 图片链接，原图最大 2 MiB、宽高各不超过 4096 像素，保存为最长边不超过 256 像素的 PNG。所有登录用户可选择共享图标；仅管理员可导入 Server 可访问的内网图片及删除未被服务使用的图标。回环、元数据和特殊地址被阻止，下载与重定向均受限制。
- 图片只在服务保存成功后加入共享库，取消预览或保存失败不保留本次图片。更换图标、删除服务不会删除共享图片；未设置或加载失败时使用本地统一默认图标。
- 节点版本更新下载完成后直接安装，不再等待业务连接排空或 DNS TTL；旧的撤出、排空阶段更新任务重试后也可继续。版本更新会重启节点并中断已有连接，客户端需重新连接。逐节点更新仍在安装与恢复确认后推进；独立“重启”操作保留原有切流、排空及中断确认。

## 更新和回退

升级前停止 Server，备份完整数据目录、Compose 与自定义配置。新增共享图标表采用增量迁移，保留账号、设备身份与服务绑定。共享图片保存在数据目录的 `service-icons/`，必须与 `nexo.db` 一起备份和恢复。

保留原挂载、网络与环境变量，将 Server 镜像标签固定为 `0.2.22`，仅更新 Server：

```bash
docker compose pull nexo-server
docker compose up -d --no-deps nexo-server
curl --fail --max-time 5 http://127.0.0.1:8280/health
```

Compose 不在当前目录时使用 `-f <文件路径>`。确认 Server 健康、Agent 重新连接及服务和共享图标可读。Agent 不需重建。

已有独立节点保留原版本与身份，内置节点随 Server 更新。后续主动发起节点版本更新时，选择可接受连接中断的时间。

回退时停止 Server，恢复原镜像、Compose 与升级前完整数据备份。恢复数据库时同步恢复图标目录，避免数据库引用与文件不一致。

## 验证范围

Rust 回归覆盖入口记录与策略状态、工作空间隔离、图标格式和尺寸限制、图片链接地址策略、下载超时及重定向、权限与 CSRF、服务保存失败清理、图标引用和删除、数据恢复，以及节点更新与独立重启流程。

浏览器验收覆盖列表与图标切换、筛选与多选保留、图标上传和共享选择、取消与失败重试、键盘访问、桌面及手机竖屏和横屏。浏览器接口仿真不代表生产公网 DNS、真实手机客户端或 ARM64 实机验收。
